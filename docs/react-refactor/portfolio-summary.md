# GlobalGates 견적 기능 React 전환

## 다시 손댄 이유

팀 프로젝트가 끝난 뒤 코드를 다시 봤을 때, 기능은 돌아가지만 제가 설명하기 어려운 부분이 많았습니다. 견적 화면은 전역 변수와 DOM 조작이 섞여 있었고 목록을 다시 그릴 때 이벤트도 다시 연결해야 했습니다. React를 공부한 뒤 새 프로젝트를 하나 더 만드는 것보다, 예전에 만든 기능의 문제를 직접 찾아 고쳐 보는 편이 제 실력을 더 잘 보여 줄 수 있다고 생각했습니다.

원본을 바로 수정하는 것은 부담스러워 `codex/react-refactor` 브랜치를 따로 만들고 작업 전 커밋에는 복구 태그를 붙였습니다. 문제가 생기면 기능별 커밋만 되돌릴 수 있게 작업도 나눴습니다.

## 바꾼 부분

제가 맡았던 견적 기능 중 목록과 등록 화면을 React로 옮겼습니다. 목록에서는 상세 보기, 기간·상태 필터, 승인과 거절을 처리합니다. 등록 화면에서는 전문가와 상품 선택, 입력 검증, 태그, AI 검토, 저장까지 이어집니다.

화면 코드 한곳에서 모든 일을 처리하지 않도록 API 호출과 화면에 쓰는 상태, 날짜 필터나 요청값 변환 같은 로직을 분리했습니다. 서버가 느리거나 실패했을 때 빈 화면만 남지 않도록 로딩, 빈 결과, 조회 실패, 처리 실패 상태도 따로 만들었습니다.

## 실제 서버에 붙이면서 고친 것

처음에는 mock 데이터로 화면 흐름을 확인했습니다. 하지만 이것만으로 끝내면 실제로 저장되는지 알 수 없어서 별도 PostgreSQL을 띄워 회원 데이터부터 다시 넣었습니다.

여기서 새 DB에는 회원 컬럼 일부가 빠져 있었고, 로그인 다음 화면에서는 구독의 `billing_key` 컬럼을 찾지 못해 오류가 났습니다. 견적 저장 때는 문자열로 넘어온 마감일이 PostgreSQL의 `date` 타입에 바로 들어가지 않는 문제도 있었습니다. 실행 중인 DB만 임시로 고치지 않고 기준 DDL과 매퍼를 수정한 뒤, 필요한 컬럼과 변환 코드가 다시 빠지지 않게 테스트를 추가했습니다.

통합 테스트 로그를 보다가 로그인 정보와 JWT가 그대로 출력되는 것도 발견했습니다. 해당 로그를 제거하고 같은 코드가 다시 들어오지 않는지 검사하는 테스트를 남겼습니다.

최종적으로 일반 회원 로그인, 전문가 검색, 상품 선택, 견적 저장, 전문가 목록 조회, 승인, 알림 생성까지 한 흐름으로 확인했습니다.

## 확인한 항목

- 프런트 로직 테스트 6개
- lint와 Vite production build
- 요청자 위조 방지와 비로그인 차단 컨트롤러 테스트
- Spring 정적 회귀 테스트
- 데스크톱과 390px 모바일 화면
- PostgreSQL 저장값, 승인 상태, 알림 2건

## 면접에서 말한다면

“기존 팀 프로젝트를 전부 새로 만든 것처럼 포장하지 않고, 제가 맡았던 견적 기능부터 React로 옮겼습니다. 전역 변수와 DOM 조작에 섞여 있던 로직을 API, 상태, 도메인 로직으로 나눴고 실패 화면도 추가했습니다. mock 화면에서 끝내지 않으려고 별도 DB에서 저장과 승인까지 확인했고, 그 과정에서 DDL 누락과 날짜 타입 오류, 민감정보 로그 문제를 찾아 테스트와 함께 고쳤습니다. 원본 브랜치는 건드리지 않았고 작업을 기능별 커밋으로 나눠 되돌릴 수 있게 했습니다.”

## 작업 범위

프로젝트 전체를 React로 바꾼 것은 아닙니다. 이번 작업 범위는 견적 목록과 등록 흐름입니다. 로그인, 커뮤니티, 채팅, 결제, 관리자 화면은 기존 Spring·Thymeleaf 구현으로 남아 있습니다.
