# 견적 목록 화면을 React로 옮긴 과정

견적 목록은 전문가가 받은 요청을 확인하고 승인하거나 거절하는 화면입니다. 제가 기존 프로젝트에서 직접 다뤘던 기능이라 React 전환의 첫 대상으로 정했습니다.

## 다시 보니 불편했던 점

기존 구현은 `service.js`, `layout.js`, `event.js`로 파일이 나뉘어 있었지만 실제 동작은 전역 객체와 DOM 선택자로 강하게 연결돼 있었습니다. 목록을 `innerHTML`로 다시 그린 다음 버튼 이벤트를 매번 재등록했고, 현재 필터나 열린 모달 같은 상태도 JavaScript 변수와 HTML 속성에 나눠 저장했습니다.

처음 만들 때는 파일을 나누는 것만으로 구조가 정리됐다고 생각했습니다. 다시 읽어 보니 기능 하나를 수정하려면 세 파일과 HTML의 선택자를 함께 확인해야 했고, 오류가 났을 때 어느 상태가 잘못됐는지 찾기도 어려웠습니다.

## 어떻게 바꿨는가

React에서는 화면에 필요한 상태를 먼저 정리했습니다. 목록 데이터, 상태 필터, 조회 기간, 선택한 견적, 확인창, 로딩과 오류를 각각 명시적인 state로 두었습니다. 화면은 이 상태에서 계산된 결과만 렌더링하도록 만들었습니다.

API 호출은 `src/api/estimations.js`로, 상태값과 날짜 필터는 `src/domain/estimation.js`로 옮겼습니다. 특히 필터 로직을 DOM과 분리한 덕분에 브라우저 없이도 테스트할 수 있게 됐습니다.

백엔드 설정이 준비되지 않은 상황에서도 같은 화면을 재현할 수 있도록 `?mock=true` 모드를 추가했습니다. 이 모드는 포트폴리오 캡처와 반응형 확인에만 사용하며, 기본 실행은 Spring API를 호출합니다.

## 오류 상태도 화면의 일부로 다뤘다

정상 목록만 보이는 화면으로 끝내지 않고 다음 상태를 따로 만들었습니다.

- 처음 데이터를 가져오는 중인 상태
- API 호출이 실패해 다시 시도해야 하는 상태
- 데이터가 없거나 필터 결과가 비어 있는 상태
- 승인·거절 요청이 실패한 상태

사용자는 실패 원인을 개발자 콘솔에서 찾을 수 없기 때문에, 문제가 생겨도 다음 행동을 알 수 있는 화면을 만드는 데 신경 썼습니다.

## 확인한 내용

- 도메인 로직 테스트 3개 통과
- `npm run lint` 통과
- `npm run build` 통과
- 상세 모달 열기와 닫기 확인
- 1440 × 1000 데스크톱 화면 확인
- 390 × 844 모바일 화면 확인
- mock 모드에서 브라우저 콘솔 오류 없음

결과 화면은 `evidence/estimation-list` 폴더에 보관했습니다. 목록 조회와 승인 흐름은 별도 PostgreSQL 환경의 실제 API에서도 확인했고, 정상 처리 후 알림 2건이 생성되는 것까지 DB에서 검증했습니다.
