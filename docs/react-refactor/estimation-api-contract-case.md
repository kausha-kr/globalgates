# 견적 등록 API 계약 보강 기록

## 확인한 문제

React 등록 화면은 요청자 ID를 보내지 않고 서버가 로그인 사용자에게서 결정하도록 만들었습니다. 그런데 Spring의 `write()` 메서드를 다시 확인해 보니 인증 객체가 없을 때도 저장 서비스를 호출하는 구조였습니다. 정상적인 보안 필터에서는 먼저 차단되지만, 컨트롤러 자체에는 방어 로직이 없어 설정 변경이나 직접 호출 시 요청자 없는 데이터가 저장될 가능성이 있었습니다.

## 고친 방식

- 견적 등록 컨트롤러가 인증 객체와 사용자 ID를 먼저 검증합니다.
- 클라이언트가 `requesterId`를 임의로 보내도 로그인 사용자 ID로 덮어씁니다.
- 인증이 없으면 `AccessDeniedException`을 발생시키고 저장 서비스를 호출하지 않습니다.
- Vite의 `/api` 프록시 대상은 `VITE_API_TARGET` 환경변수로 분리했습니다.

## 테스트로 남긴 증거

`EstimationAPIControllerTest`에서 다음 두 경우를 고정했습니다.

1. 요청 본문의 `requesterId=999`가 로그인 사용자 ID `7`로 교체되는지 확인
2. 인증 정보가 없는 요청에서 `EstimationService.write()`가 호출되지 않는지 확인

테스트 실행 과정에서 기존 테스트 두 개가 변경된 서비스·매퍼 계약을 따라가지 못해 전체 테스트 소스가 컴파일되지 않는 문제도 발견했습니다. 제품 코드는 바꾸지 않고 테스트 호출만 현재 시그니처에 맞춰 복구했습니다.

```text
> Task :compileTestJava
> Task :test
BUILD SUCCESSFUL
```

## 실제 DB 통합 검증에서 찾은 오류

기존 로컬 DB에는 영향을 주지 않기 위해 PostgreSQL 18로 포트 `55432`의 임시 클러스터를 만들고 기준 DDL을 적용했습니다. 이 과정에서 자동 테스트만으로는 보이지 않던 오류 두 개를 재현했습니다.

1. 기준 DDL의 `tbl_member`에 `member_country`, `member_language`가 없어 로그인 쿼리가 실패했습니다.
2. 화면과 DTO의 마감일은 문자열인데 DB 컬럼은 `date`라 견적 저장 시 500 오류가 발생했습니다.

기준 DDL과 멱등 마이그레이션에 회원 컬럼을 추가했고, MyBatis 저장 쿼리에서 마감일을 `date`로 명시 변환했습니다. 같은 문제가 돌아오지 않도록 `StaticQaRegressionTest`에도 스키마와 매퍼 계약 검사를 추가했습니다.

## 최종 통합 결과

테스트용 일반 회원과 전문가가 실제 로그인 API에서 JWT 쿠키를 발급받은 뒤 다음 흐름을 확인했습니다.

- 전문가 검색 1건, 상품 조회 1건
- 견적 저장 성공
- 요청 본문의 가짜 요청자 `999` 대신 로그인 사용자 `1` 저장
- 수신자 `2`, 상품 `1`, 마감일 `2026-10-20`, 태그 2개 저장
- 전문가 계정의 수신 목록에서 동일한 견적 ID 조회
- 전문가 승인 후 DB 상태 `approve`
- 요청 알림과 승인 알림 총 2건 생성

민감정보를 제외한 실행 결과는 `evidence/estimation-api/06-integration-result.txt`에 남겼습니다.

## 검증 중 발견한 로그 문제

실제 로그인 요청을 확인하는 과정에서 로그인 DTO 전체, JWT 원문, 인증 객체가 로그에 출력되는 것도 발견했습니다. DTO에는 평문 비밀번호가, 인증 객체에는 비밀번호 해시가 포함됩니다. 로그인 메서드의 AOP 대상 지정을 제거하고 관련 객체 전체 출력과 토큰 원문 출력을 없앴습니다. 인증 필터에는 필요한 경우 사용자명만 `debug` 수준으로 남도록 바꿨습니다.

회귀 테스트에서는 로그인과 인증 필터에 민감 객체를 출력하던 기존 로그 패턴이 다시 들어오지 않는지 확인합니다.
